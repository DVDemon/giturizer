# ADR-0001: Бэкенд на Python + FastAPI

- **Статус:** Принято
- **Дата:** 2026-11-23

## Контекст

Нужен бэкенд-оркестратор: REST API, управление проектами/запусками, постановка задач,
вызов анализаторов и сборка результата. Ключевой фактор — плотная интеграция с языковым
инструментарием анализа (pyan/pyreverse/code2flow — Python; dependency-cruiser/madge — Node;
ArchGuard — JVM).

## Решение

Использовать **Python + FastAPI** для `api` и `worker` (Celery). Взаимодействие с анализаторами —
через Docker-контейнеры (см. ADR-0005), поэтому язык бэкенда не обязан совпадать с языком инструмента.

## Альтернативы

- **Go** — быстрый монолит, но Python-инструменты пришлось бы звать как контейнеры (что и так
  планируется), а парсинг IaC/API удобнее в Python.
- **Java/Kotlin (Spring)** — максимальная интеграция с ArchGuard, но тяжелее для итераций.
- **Node.js/TypeScript** — единый стек с фронтендом и родная интеграция с dependency-cruiser/madge.

## Последствия

- Быстрая разработка, богатая экосистема парсинга (PyYAML, ruamel.yaml, tree-sitter, proto/graphql парсеры).
- Общий язык для `api`, `worker` и вспомогательных скриптов генерации Structurizr-вывода.
- Минус: GIL/производительность — некритично, т.к. тяжёлая работа вынесена в контейнеры анализаторов.
