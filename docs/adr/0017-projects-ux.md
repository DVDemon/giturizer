# ADR-0017: Два таба, пагинация проектов и прогресс сканирования

- **Статус:** Принято
- **Дата:** 2026-11-24

## Контекст

UI загружал все проекты и все запуски сразу, сайдбар не масштабировался на
десятки проектов, а долгие пайплайны (клон 22 submodules + ArchGuard) показывали
только «выполняется» без стадии и прогресса.

## Решение

- Главная страница — **два таба**:
  - **Проекты** — таблица с серверным поиском (имя/URL), фильтром провайдера,
    сортировкой (имя/URL/создание/последнее сканирование) и пагинацией
    (10/20/50/100). Колонки: имя, URL, дата последнего сканирования.
  - **Сканирование** — детали выбранного проекта: текущий/последний запуск.
- Клик по проекту открывает таб «Сканирование» для этого проекта; поддерживаются
  deep links `#scan/<project_id>` и возврат «Все проекты».
- В `analysis_runs` добавлены `stage`, `progress`, `technologies_count`,
  `services_count`, `api_count` (миграция 0006 с backfill по историческим запускам).
  Пайплайн обновляет стадию/прогресс/счётчики после каждого этапа:
  clone → detect → analyzers → deployment/API → model → Structurizr → graph → done.
- Счётчики: технологии — найденные детектором; сервисы — контейнеры в
  архитектурной модели; API — извлечённые контракты.
- UI опрашивает `GET /api/runs/{id}` каждые 2.5 с, пока запуск в очереди/выполняется;
  отдельный таймер обновляет длительность.
- `GET /api/projects` возвращает конверт `{items,total,page,per_page}` и
  `last_scan_at` (max `created_at` запуска); параметры `search`, `provider`,
  `sort`, `order`, `page`, `per_page`.

## Альтернативы

- Клиентская пагинация — не масштабируется и требует выгрузки всех проектов.
- WebSocket/SSE для прогресса — избыточно для одного пользователя; polling проще.
- Отдельный сервис прогресса — нет необходимости, поля в БД достаточно.

## Последствия

- (+) Список проектов работает при сотнях записей, фильтры/сортировка на сервере.
- (+) У долгого пайплайна видны стадия, прогресс, длительность и счётчики.
- (+) Deep links на проект.
- (−) Изменён контракт `GET /api/projects` (теперь конверт, а не массив).
- (−) Polling создаёт фоновую нагрузку (2.5 с на активный запуск).
