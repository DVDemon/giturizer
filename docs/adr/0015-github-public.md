# ADR-0015: Публичные GitHub-репозитории и автоопределение ветки

- **Статус:** Принято
- **Дата:** 2026-11-24

## Контекст

Сервис создавался как GitLab-ориентированный: поле `gitlab_url`, GitLab-токен,
ветка по умолчанию `main`. Требуется загружать **публичные репозитории GitHub**
без токена; при этом ветка по умолчанию у проектов бывает `master`, `main` и др.

## Решение

- **Провайдер** определяется по host URL (`github`, `gitlab`, `other`) и хранится
  в `projects.provider`; поле URL переименовано в `repo_url`, токен — в `token_encrypted`.
- Публичные репозитории GitHub/GitLab клонируются **анонимно**; токен опционален
  (GitLab — Basic `oauth2:<token>`, GitHub — `x-access-token:<token>`).
- `default_branch` **необязателен**. Если не указан — определяется
  `git ls-remote --symref <url> HEAD`; при ошибке используется `main`.
  Определённая ветка сохраняется в проекте.
- Если указанная ветка отсутствует, выполняется один ретрай на ветку по умолчанию.
- API принимает `repo_url`; старое поле `gitlab_url` поддерживается как alias.
- Миграция `0005`: переименование колонок, `provider`, nullable `default_branch`.

## Альтернативы

- Отдельные сущности/таблицы для GitHub и GitLab — избыточно: клонирование
  и анализ одинаковы, различается только auth.
- Всегда требовать ветку — ломает UX публичных GitHub-репозиториев.
- Только анонимный клон без токена — закрывает public, но не future private.

## Последствия

- (+) Публичные GitHub-репозитории подключаются в один шаг (URL без токена).
- (+) Ветка определяется автоматически, меньше ошибок `Remote branch not found`.
- (−) В pipeline добавляется сетевой вызов `git ls-remote` перед клоном.
- (−) Схема БД меняется (миграция 0005); API-поле переименовано с backward-compatible alias.
- Приватный GitHub с PAT поддерживается, но требует токена с доступом на чтение.
