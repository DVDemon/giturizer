# ADR-0007: Источники API

- **Статус:** Принято
- **Дата:** 2026-11-23

## Контекст

Спецификации API должны строиться из кода/артефактов в репозитории и быть привязаны к
контейнерам/сервисам архитектурной модели.

## Решение

Извлекать API из четырёх групп источников:

1. **OpenAPI / Swagger** — готовые `openapi.yaml/json` и Swagger-аннотации.
2. **gRPC / protobuf** — `*.proto` (RPC-сервисы).
3. **GraphQL** — схемы `*.graphql`/`*.gql`.
4. **Аннотации фреймворков** — Spring/REST, JAX-RS (Java), ASP.NET (C#), FastAPI (Python),
   express-роуты (Node).

Нормализация: канонический формат — **OpenAPI 3.x (JSON)** + метаданные (владелец-контейнер,
файл-источник, фреймворк); для gRPC/GraphQL сохраняется и нативная схема.

## Альтернативы

- Только OpenAPI (пропускаем gRPC/GraphQL/аннотации) — проще, но покрытие меньше запрошенного.
- Хранить каждый формат «как есть» без нормализации — теряется единый просмотр и сопоставление.

## Последствия

- Единый просмотр API в Swagger UI/Redoc, сопоставление endpoint ↔ сервис в графе.

> Дополнение: Swagger UI/Redoc заменены API-каталогом (ADR-0018).
- Требуются парсеры protobuf/GraphQL и языковые анализаторы аннотаций.
