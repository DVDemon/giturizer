# ADR-0004: Асинхронное выполнение через Redis + Celery

- **Статус:** Принято
- **Дата:** 2026-11-23

## Контекст

Анализ репозитория (клонирование, запуск нескольких анализаторов, парсинг IaC/API) — длительная
операция (минуты). Синхронный HTTP-запрос упрётся в таймауты и плохой UX.

## Решение

Асинхронная модель: `api` принимает URL, создаёт `analysis_run(status=queued)` и публикует задачу в
очередь; **Celery worker** выполняет пайплайн и обновляет статус/результат; `web` поллит статус
(или подписывается на обновления).

- Брокер/бэкенд — **Redis**.
- Идемпотентность: запуск по `commit_sha` + конфигу; повторные запуски создают новый `analysis_run`.

## Альтернативы

- **Синхронно (длинный HTTP)** — просто, но таймауты и блокировка воркеров.
- **Workflow-движок (Temporal/Argo)** — полноценные пайплайны, ретраи, DAG; избыточно для v1.

## Последствия

- Устойчивость к долгим анализам, горизонтальное масштабирование воркеров.
- Добавляется компонент `redis` и логика отслеживания статуса задачи.
