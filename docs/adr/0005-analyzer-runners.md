# ADR-0005: Отдельный Docker-образ на каждый анализатор

- **Статус:** Принято
- **Дата:** 2026-11-23

## Контекст

Пайплайн использует разнородные инструменты с несовместимыми зависимостями:
ArchGuard scanner (JVM), doxygen + cpp-dependencies (C/C++ toolchain), pyan + pyreverse (Python),
dependency-cruiser + madge (Node). Устанавливать всё в один рантайм рискованно (конфликты версий,
огромный образ).

## Решение

Для каждого инструмента/группы инструментов — **отдельный Docker-образ**:

- `analyzer-archguard` — ArchGuard scanner CLI.
- `analyzer-cpp` — doxygen + cpp-dependencies.
- `analyzer-python` — pyan + pyreverse (pylint).
- `analyzer-node` — dependency-cruiser + madge.

Раннер поднимает контейнер на этап анализа, монтирует рабочую директорию с клоном, собирает
stdout/JSON-артефакты.

## Альтернативы

- **Один «толстый» образ** — проще деплой, но тяжёлый образ и конфликты зависимостей.
- **Внешний ArchGuard-инстанс + локальные CLI** — готовый ArchGuard-бэкенд отдельно; для v1
  достаточно scanner CLI в контейнере.

## Последствия

- Чистая изоляция и воспроизводимость; независимое обновление версий инструментов.
- Нужен механизм запуска контейнеров (см. ADR-0011) и управление образами.
