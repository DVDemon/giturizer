# ADR-0027: Дедупликация контейнеров C4 по источнику сборки

- **Статус:** Принято
- **Дата:** 2026-11-26

## Контекст

В репозитории BeeAtlas есть корневой `docker-compose.yml` и отдельные
`services/*/docker-compose.yml`. Один и тот же контейнер описывается дважды:
в корневом compose — `build: ./services/products-service`, в сервисном —
`build: .`. Docker-контексты указывают на один каталог, но raw-строки разные.
C4 показывал два контейнера.

## Решение

- В `deployment_extract` build context и Dockerfile нормализуются относительно
  репозитория:
  `build_context_normalized`, `dockerfile_normalized`, `build_source`.
- В `build_model` контейнеры дедуплицируются по `build_source`.
- Каноническим остаётся первый встретившийся сервис (обычно корневой compose).
- Остальные compose-сервисы становятся алиасами того же container id;
  deployment instances тоже дедуплицируются.
- Внешние системы (`postgres`, `rabbitmq`, ...) дедуплицируются по имени.
- Если build source разный (например, `Dockerfile` и `Dockerfile.test`) —
  контейнеры остаются разными.

## Последствия

- (+) C4 не дублирует один и тот же контейнер.
- (+) Сохраняется информация о разных сборках из разных Dockerfile.
- (+) Алиасы сервисов продолжают ссылаться на канонический контейнер.
- (−) Требуется пересборка модели/повторный анализ для старых снапшотов.
- (−) Нужно корректно резолвить контекст относительно compose-файла.
