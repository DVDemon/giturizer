# ADR-0012: Доступ к GitLab — токен vs SSH-ключ

- **Статус:** Принято
- **Дата:** 2026-11-23

## Контекст

Worker клонирует приватные репозитории GitLab. Нужен способ аутентификации.

## Решение

Выбран вариант **A — Personal/Project access token (HTTP)**: токен передаётся в URL или
заголовке, хранится зашифрованно, используется только на время клонирования. Права токена —
`read_repository` (минимум). Для разных проектов — отдельные токены; в клоне используется
`--filter`/shallow где возможно.

## Альтернативы

- **B. SSH deploy key** — ключ монтируется в worker; сложнее управление ключами и нет тонкого
  контроля разрешений уровня токена. Не выбран для v1.
- **Анонимный клон** — только публичные репо, недостаточно.

## Последствия

- Токен шифруется в БД (Fernet/KMS), не попадает в логи/артефакты; передаётся только на время работы.
- Для SSO-клонирования и крупных приватных репо может понадобиться SSH как fallback (v2).
- Нужна ротация токенов и отзыв.
