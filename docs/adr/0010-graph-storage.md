# ADR-0010: Хранение графа архитектуры в Neo4j

- **Статус:** Принято
- **Дата:** 2026-11-23

> Уточнение 2026-11-25: интерактивный граф убран из UI; Neo4j остаётся
> хранилищем для API `/graph/elements` и `/graph/dependencies`.

## Контекст

Граф архитектуры (элементы + связи) нужно хранить так, чтобы веб-вьюер строил Cytoscape-граф и
отвечал на запросы зависимостей, не перегенерируя всё при каждом чтении. Основные сценарии:
«кто транзитивно зависит от X», обнаружение циклов, анализ связности, произвольная навигация по
цепочкам зависимостей между сервисами/контейнерами/компонентами.

## Решение

Хранить архитектурный граф в **Neo4j**:

- **Узлы** — элементы модели: `softwareSystem`, `container`, `component`, `deploymentNode`
  (со свойствами: `element_id`, `name`, `technology`, `tags`, `concept`, `run_id`).
- **Рёбра** — связи с типом и свойствами (`relationship_type`, `description`, `technology`, `tags`,
  `run_id`).

**PostgreSQL остаётся** источником истины для метаданных и артефактов: проекты, запуски,
внутренняя C4-модель, JSON-отчёты, спецификации API, реестр технологий, deployment-модель, артефакты.
Снапшот `architecture_snapshots.graph` (JSONB) сохраняется как «слепок»/экспорт, но **не** является
источником для графовых запросов.

Персист: на шаге Persist пайплайн пишет метаданные в PostgreSQL, а граф — в Neo4j через идемпотентный
`MERGE` по стабильному `element_id` (в рамках `run_id`). Транзитивные запросы — Cypher
(`MATCH path = (a)-[*1..N]->(b) ...`).

## Альтернативы

- **JSONB + опциональные adjacency-таблицы** — проще, один компонент хранения, но транзитивные
  запросы и графовая аналитика дороже и пишутся вручную; отклонено.
- **Только JSONB без adjacency** — отклонено по той же причине.

## Последствия

- (+) Нативные графовые запросы и аналитика (транзитивные зависимости, циклы, связность);
  удобная интеграция с Cytoscape для интерактивной навигации.
- (+) Чёткое разделение: PostgreSQL — «документы и история», Neo4j — «связи и навигация».
- (−) Добавляется компонент `neo4j` в docker-compose (память, том, healthcheck).
- (−) **Двойная запись** (PostgreSQL + Neo4j) требует согласованности: либо синхронная запись в
  одном шаге Persist с компенсацией при сбое, либо ETL из JSONB-слепка в Neo4j с идемпотентностью.
  Нужны стратегия восстановления и ре-импорт снапшота.
- (−) Два хранилища — резервное копирование и мониторинг сложнее.
- Уточняет [ADR-0002](0002-database.md): PostgreSQL больше не хранит граф как основной источник.
