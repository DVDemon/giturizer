# ADR-0020: Graphviz C4 container diagram (по мотивам VARP)

- **Статус:** Принято
- **Дата:** 2026-11-24

## Контекст

VARP ([tech-beeline/varp](https://github.com/tech-beeline/varp)) — VS Code-расширение
для Structurizr DSL. Оно **не анализирует исходники** и не выводит контейнеры из
Dockerfile/compose: container view в нём объявляется в DSL. Полезная часть VARP —
авто-раскладка C4-видов: DOT → Graphviz → координаты в Structurizr JSON.

Наш сервис уже строит Structurizr workspace из кода, но C4 рисовал через Mermaid:
для больших систем это даёт менее управляемую раскладку.

## Решение

- Собственный **DOT builder** из Structurizr JSON (`softwareSystems`,
  `containers`, `relationships`), без зависимости от Langium/VSCode.
- Рендер через **Graphviz `fdp`** (компактнее `dot` для десятков контейнеров и
  внешних систем); SVG отдаётся эндпоинтом `GET /api/runs/{id}/c4.svg`.
- В DOT:
  - systems с контейнерами — кластеры (`subgraph cluster_*`), контейнеры — узлы;
  - внешние системы — только связанные с контейнерами/системой, дубликаты по имени
    схлопываются;
  - связи — с `ltail`/`lhead` для кластеров; названия и подписи экранируются.
- Graphviz ставится в API-образ (`graphviz`, `fonts-dejavu-core`).
- UI: вкладка C4 по умолчанию открывает Graphviz, переключатель Mermaid сохранён;
  масштаб 100/150/200%, скачивание SVG.

## Альтернативы

- Переиспользовать код VARP целиком — высокая связанность с Langium/VS Code,
  отдельная сборка Graphviz WASM; не нужно для SSR-рендера.
- Graphviz WASM на клиенте — ещё одна тяжёлая зависимость; серверный SVG проще.
- Оставить только Mermaid — меньше контроля над C4-раскладкой.

## Последствия

- (+) Читаемая container-диаграмма при большом числе контейнеров.
- (+) Нет JS/WASM Graphviz на клиенте; SVG кешируется, скачивается.
- (+) VARP остаётся референсом; код независим, лицензионных заимствований нет.
- (−) API-образ вырос на Graphviz; нужен системный `fdp`.
- (−) Для 40+ контейнеров подписи мелкие на 100% — помогает масштаб/скролл.
- Graphviz распространяется под EPL-1.0; используем системный пакет, не встраиваем
  исходники.
