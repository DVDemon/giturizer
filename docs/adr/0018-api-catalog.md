# ADR-0018: API-каталог вместо Redoc

- **Статус:** Принято
- **Дата:** 2026-11-24

## Контекст

На реальном проекте извлекается 159 API-источников: 1 OpenAPI (31 операция)
и 158 annotation-конспектов (540 endpoint). Текущая вкладка показывала все
159 источников «чипами» с полными путями к файлам — это нечитаемо. Кроме того,
Redoc использует hash-ссылки (`#tag/...`), которые конфликтуют с hash-роутингом
приложения (`#scan/<id>`).

## Решение

- Все операции из всех источников агрегируются в **единый каталог**:
  OpenAPI, annotations, gRPC, GraphQL.
- Каталог: поиск по path/summary/operationId/сервису, фильтры по сервису,
  HTTP-методу и типу источника, пагинация по 50.
- Клик по операции открывает **панель деталей**: параметры, тело запроса,
  ответы и JSON-схемы; для annotations — файл-источник и фреймворк.
- Deep link: query-параметры `?api=<specIndex>&op=<id>` при сохранении
  hash-маршрута `#scan/<id>`; при загрузке открывается вкладка API и выбранная
  операция. Redoc и его hash-ссылки удалены.

## Альтернативы

- Redoc + нормальный picker — быстрее, но остаётся нечитаемым для 158
  annotation-источников и конфликт hash.
- Swagger UI — та же проблема с несколькими спецификациями.
- Трёхпанельный explorer — следующий шаг, если понадобится навигация по схемам;
  текущий каталог уже даёт поиск и детали.

## Последствия

- (+) 571 операция ищется и фильтруется в одном месте.
- (+) Больше нет стены из 159 чипов и конфликта `#tag/...`.
- (+) Единый стиль Beeline; метод-бейджи, схемы, deep links.
- (−) Схемы показываются как JSON, без интерактивного «Try it out».
- (−) `@stoplight/elements`/Scalar можно подключить позже для richer schema view.
