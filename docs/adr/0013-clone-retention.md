# ADR-0013: Очистка клонов после анализа (ретеншн рабочего volume)

- **Статус:** Принято
- **Дата:** 2026-11-24

## Контекст

Каждый запуск клонирует репозиторий в общий volume `/data/repos/<run_id>`. Без очистки volume
растёт линейно от числа запусков (репозитории бывают крупными), а клон после завершения анализа
не нужен — результаты уже сохранены в PostgreSQL и `/data/artifacts`.

## Решение

- После завершения запуска (успех или ошибка) каталог клона удаляется по умолчанию.
- Флаг `KEEP_REPOS=true` (или параметр `keep_repos` в `execute_run`) оставляет клон для отладки.
- Артефакты анализа сохраняются в `/data/artifacts/<run_id>/`; их ретеншн — ручной/периодический
  (см. runbook, §6).
- Удаление проекта каскадно чистит записи БД; файлы артефактов удаляются вручную.

## Альтернативы

- Хранить клоны всегда — проще для отладки, но быстро исчерпывает диск.
- Хранить по TTL внутри приложения — требует фонового планировщика; отложено.

## Последствия

- Объём volume ограничен артефактами, а не историей клонов.
- Для разбора инцидентов нужно включать `KEEP_REPOS` заранее (или перезапускать анализ).
- Очистка выполняется в `finally`, поэтому не мешает фиксации статуса запуска.
