# ADR-0002: PostgreSQL + JSONB как основная БД

- **Статус:** Принято (уточнён ADR-0022)
- **Дата:** 2026-11-23

> **Уточнение (ADR-0010):** хранение **графа архитектуры вынесено в Neo4j**. Настоящий ADR остаётся
> в силе для метаданных, внутренней C4-модели, JSON-отчётов, спецификаций API, реестра технологий, deployment-модели
> и артефактов.

> Уточнение 2026-11-25: Neo4j удалён, источник данных — только PostgreSQL
> (см. [ADR-0022](0022-postgres-only.md)).

## Контекст

Нужно хранить: метаданные проектов и запусков, граф архитектуры (элементы + связи), спецификации
API, реестр технологий, модель развёртывания и артефакты. Графовые запросы («кто транзитивно зависит
от X») желательны.

## Решение

Использовать **PostgreSQL** для метаданных и артефактов. Реляционная часть — для
проектов/запусков/артефактов; структурированные и слабоструктурированные результаты (API,
технологии, deployment, слепок графа) — в столбцах **JSONB**. Граф как источник для графовых
запросов хранится в **Neo4j** (см. [ADR-0010](0010-graph-storage.md)).

## Альтернативы

- **Гибрид PostgreSQL + Neo4j** — максимум возможностей; выбран (см. ADR-0010).
- **Только JSONB в PostgreSQL** — отклонено: транзитивные запросы и графовая аналитика дороже.

## Последствия

- Два компонента хранения: PostgreSQL (метаданные/артефакты) + Neo4j (граф).
- docker-compose и резервное копирование включают оба хранилища.
- Транзитивные/графовые запросы выполняются в Neo4j (Cypher).
